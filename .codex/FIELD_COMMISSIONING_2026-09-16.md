# Linux 工控机现场联调版：使用与改造说明

## 状态与边界

### 2026-10-15：机械臂稀疏规划路径自适应采样

已修复“仿真可以运动，真实开始运行却报相邻关节差超限”的适配问题：规划器的两个端点不等于两个很近的小点。现在在冻结真实计划时，沿每条原关节线段补点，同时处理粗定位、显式返程及自动逆向返程；不重新求IK、不改目标、不自动折返±360，也不跨过原路径拐点。

- **现场JSON通常保持 `"maxJointStepDeg": 5.0` 即可**。它现在决定规划路径的采样密度，不是整段允许转动的总角度；参数范围仍为0.01～10，不要再改成100。现场J1/J2单步微调仍有原单步限制。六轴jointMin/Max必须按实际型号/控制器软限位填写，不能以全部±360冒充已核对的真实限位。
- 本机已记录的路径J5从约−90°到−254.36°，原线段角差约164.36°；5°采样时这一段自动分为33段。原清单包含重复起点，所以粗定位为34点。这是采样计算示例，不是实物运动验收。
- 原规划段的“角差÷估速＋缓冲、最小/最大等待”只算一次，再分摊给这一段的新点，避免每个补点重复加缓冲。ACK耗时计入间隔，队列窗口/网络慢时仍可增加等待；不承诺速度或总耗时与旧包完全一致。真实速度仍由robotSpeedPercent决定，不由采样步长决定。
- 段内仍为逐条接受应答、`cp=50`、最多16条未确认窗口，**不逐点等待静止，也不逐点Stop**；只有最后一条`cp=0`，随后仍须本条命令ID＋新鲜反馈＋空闲＋六轴误差合格持续0.3秒。最后一个点的节流间隔为0，不表示跳过实际到位检查。
- 返程声明起点与粗定位终点不一致时，仍拒绝运行；缺少声明起点且首点不匹配，也不会自动插值补接。实物实际起点、限位、反馈、故障和停止保护保持。补点保留指令中的关节线段/拐点顺序，不保证控制器CP平滑后的实物TCP轨迹与仿真逐帧插值精确重合，需监护验收。
- 全流程模拟复用同一采样检查（默认5°，不读取实物许可/软限位），但动画继续沿原线段逐帧插值，不给每个补点重复播放0.25秒。模拟成功不等于现场限位、起点或物理到位已验证。

新构建的`build-info.json`诊断标识为 **`sampled-trajectory-v2-2026-10-15`**；正式半自动报告新增`trajectory-plan.json`，逐任务保存起点、原始六轴角度、补点后角度、原点编号/份额、原最大角差与发送间隔，便于复查。不应把`maximumSourceDeltaDeg`大于步长当成错误：它就是补点前的大线段；检查的是补点后的相邻角差。`run.log`中的`[半自动轨迹]`含目标/阶段、点号、命令ID、CP、间隔和六轴目标。限位/残余步长错误现在给出目标、阶段、点/轴及角度，不再仅提示笼统超限。

**部署与下一次验证：**

1. Unity退出Play，等待导入，检查Console。非Play可运行`Tools → Validation → Semi automatic toolbar (no hardware)`，新增Unity JSON采样报告序列化检查，不访问设备/生产数据库。
2. 重新生成任务，再完整构建Linux到新目录部署；源码修改不更新现有v1.12.7等旧包。现场JSON不自动覆盖，备份后核对采样步长、真实软限位、实际起点与User/Tool。若此前写了100，改回5并保存。
3. 先监护单目标：核对原始/采样角度，确认粗定位连续、整段末点等待、人工确认后接触、返程及取消均符合预期，再做多目标。异常时提供整份报告，尤其`trajectory-plan.json`、`trajectory-timing.json`、`build-info.json`及`run.log`。

当前源码及无硬件回归已验证；Unity预览菜单/实际Play和实物效果仍需人工确认。本次不修改Python拧紧算法、工具标定、底盘协议或电缸超时规则。

### 2026-10-14：底盘新/旧模式开关（真实运行）

位置：左上“现场联调 / 参数”，在实时反馈选项下方勾选 **底盘旧模式：定时等待（不查询任务完成状态）**。

- 不勾选（默认）：新模式，3055/3056应答后查询1020，观察本段RUNNING→COMPLETED才进入下一阶段；失败不会自动降级。
- 勾选：旧模式，仍用相同3055平动/3056旋转和原方向；等待“距离或弧度 ÷ 对应速度 + 缓冲”，不查询1020。等待结束后流程暂停，底部原程序按钮显示 **确认底盘**。在安全区域核对底盘实际位置/朝向正确且已停稳，点击后才允许升降/机械臂继续；此按钮不会启动拧紧。机械臂之后粗定位末点到位，仍有原先独立的“确认并拧紧”关卡。

切换后点击“保存参数”，重新核对并勾选本次安全确认，再“开始运行”。保存到同一个field-commissioning.json，下一次启动可继续用所选模式；运行/停止未确认时不能切换，外部改文件也不会改变本次已冻结的配置。旧JSON缺少新字段时仍默认新模式，不会静默降级。无底盘导航任务时此选项不产生额外关卡；离线模拟仍只走动画，不调用两条真实底盘路径。

也可在退出流程后外部修改JSON：`"useLegacyChassisTiming": true`为旧模式，false为新模式，按原方法重新加载/重新进入界面。

旧模式等待参数位于JSON的legacyChassisTiming：

```json
"legacyChassisTiming": {
  "commandBufferSeconds": 0.5,
  "rotationBufferSeconds": 5.0,
  "translationBufferSeconds": 5.0,
  "minWaitSeconds": 0.2,
  "maxWaitSeconds": 0.0
}
```

这是当前RunScene原等待节奏的默认值，不自动继承工控机旧包曾临时修改过的数值。0上限表示不设配置上限，但每段仍有600秒硬边界；正上限若会截短预计运动时间则拒绝，不提前放行。真实速度仍来自现场JSON的chassisSpeedMS（m/s）及chassisTurnRadS（rad/s），不是机械臂速度滑条。

兼容开关只改变完成判断，不回退所有通信安全检查：两种模式都要有正确的导航连接/IP、匹配应答，断线/拒绝/应答超时/停止均中止，不自动重发运动。旧模式不要求状态端口就绪，但也无法自动检测底盘内部的暂停/任务失败；人工确认不可省略。若原问题是包版本、流水号或发送应答不匹配，旧模式仍可能失败，不能以兼容模式绕过协议错误。3003应答不证明物理停稳，停止/切换前仍须现场确认，必要时硬件急停。

日志/报告/运行历史明确区分“新模式完成状态确认”和“旧模式估时结束/人工确认”，不把旧模式isDispatched当作自动实物到位证据。请重新完整构建到新目录部署；旧TEST包不会因修改源码自动更新。无设备回归通过，Unity批处理仍提示工程被占用，开关位置、保存重启及两类确认按钮仍须人工验收。

`粗定位动画 → 等待继续 → 小幅模拟视觉 → 模拟卡入/拧紧/退出 → 精调撤回/返程 → 下一目标再次等待`

2. 在真实运行页勾选“全流程验证（模拟）”，点“开始运行”。不用连接设备，也不用勾选现场实物安全许可。此模式仍按所有目标演示，“单目标”选项和实物实时同步临时禁用。
3. 粗定位动画结束后，上方提示等待；底部原“启动程序”按钮变为“继续（模拟）”，上方也提供同义继续按钮。二者共用一次性关卡，不会重复推进。
4. 点击继续后才播放小幅精调，再运行本机Python模拟接触周期，成功后返程并到下一目标重新等待。默认小幅精调峰值J1约0.8°、J2约0.5°、第七轴2mm；前六项度转弧度，第七项米。可在ConnectCommander的mockVisionTrajectory配置，不需改现场JSON；本次开始后参数已复制，修改下次生效。

模拟不依赖实物反馈：这里的“粗定位完成”仅指模型动画结束，Python结果为SIMULATED_OK，不会伪造真实力矩曲线或实物到位证据。Python中的接触模拟仍通过本机Gateway执行数值流程，不保证3D模型在拧紧阶段呈现实物插入/电批转动动画；小幅视觉精调动画可见。

离线启动现在使用独立隔离标志SERVO_SIMULATION_ONLY=1，不连接/复位电批，且拒绝实物命令；取消也不发送无主机械臂Stop。真实入口仍保留原算法和停止方式。若提示“实物/隔离模拟模式不匹配”，先停止本次流程，再关闭原拧紧服务，重新开始所需模式；不要忽略提示混用旧服务。无需预先点击“启动程序”，离线流程会自动准备模拟服务。

当前无硬件协程/按钮逻辑编译、协议回归和真实隔离Python子进程冒烟已通过；GUI还需人工验收。非Play可运行 `Tools → Validation → Semi automatic toolbar (no hardware)` 检查真实/模拟按钮与StepRun父标签，随后Play检查：每点均暂停、精调小幅运动、双击不重复、等待/执行时取消、不出现实物许可大面板、退出后按钮恢复。

**操作顺序：**

   真实全局速度使用现场JSON的 `robotSpeedPercent`（不是估速参数armJointSpeedDeg）；底盘/升降速度也使用现场JSON。请在开始前核对为已验证的值。运行期间速度滑条、IP、单目标/模拟选项锁定，本次参数不会随界面操作改变；停止未确认时继续锁定。

6. 出现“等待人工对位确认（视觉未执行）”后，原“启动程序”按钮变为 **“确认并拧紧”**。在安全区域确认当前末端确实具备卡入条件，再点击一次；参数面板内也有同一继续入口。此按钮执行完整卡入—拧紧—退出，不是旁边仅控制电批正转的“开始拧紧”。
7. 继续前再次核对新鲜反馈、暂停位姿/命令/坐标系和电批就绪。双击只放行一次，下一目标需要新确认。不要在等待期间用示教器移动、切坐标系或启动其他任务；位姿/命令改变会使许可失效。等待不是安全停机，不能作为人员进入工作区的许可。
8. 仅整个周期成功后才进入返程。返程沿冻结的已知路径，实际关节必须接近声明起点；如果退出后不相符，明确中止，不自动大步连接或补偿。多目标模式返程确认后自动前往下一目标，但再次等待人工继续。
9. 自动流程期间手动电批正转/反转互斥禁用；“立即停止”始终可用于本次流程，即使Python尚未就绪。停止取消后续任务并请求相关设备停止，未确认不解锁，不自动返程或下一目标；重试停止确认仅解锁，不续跑。仍须保留硬件急停。

| toolIp/toolPort | 电批地址；启动/复用Python后核对服务实际报告地址 |
| chassisIp/liftIp/liftPort | 底盘及升降地址；底盘继续使用19204/19205/19206 |
| toolNumber | 与真实TCP/工具坐标配置一致，必须核实；接触沿工具X负向卡入、正向退出 |
| visionJ1Deg/visionJ2Deg | 当前实测关节角加偏移；默认0，不会凭空使用全零关节目标；现场可先选已核实的小偏移 |
| jointMinDeg/jointMaxDeg | 各6个数，必须按实物型号/软限位填写；不得照抄别的机器人 |
| maxJointStepDeg | 相邻目标及实际当前位置到下一目标最大关节变化；默认5°，最大10° |
| jointToleranceDeg/jointTimeoutSeconds | 实际到位容差/超时；到位还须空闲状态稳定0.3秒 |
| robotSpeedPercent | 调试速度比例，默认1%，允许1～10% |
| insertionMm/withdrawalMm | 卡入/退出距离，mm；默认各20；不是视觉J1/J2偏移 |
| contactSpeedMmS/contactStepMm | 接触速度/步长；步长÷速度不得超过网关5秒单次上限 |
| contactStageTimeoutSeconds/tightenTimeoutSeconds | 每个卡入/退出阶段、拧紧结果等待的超时 |
| beforeTightenSeconds/beforeExitSeconds | 两段等待，默认各5秒 |
| forceLimitN/momentLimitNm/lateralLimitN | 接触保护阈值；上限保持既有30N/10Nm，不得为通过测试随意放宽 |
| chassisTimeoutSeconds/chassisStartTimeoutSeconds | 底盘每段总超时/观察到开始运行的期限 |
| chassisSpeedMS/chassisTurnRadS | 底盘m/s、rad/s；现有坐标映射与转向规则未改，必须现场验证 |
| liftSpeedMmS/liftMinMm/liftMaxMm | 升降速度和实际行程边界；含升降任务必须填写有效边界 |
| firstTarget | 从1开始的目标编号；单目标测试该目标，连续运行从该目标到末尾 |

面板提供：

1. **环境检查（无设备）**：只校验Python/依赖/脚本语法/字体和Agg绘图，不启动驱动服务、不连接设备。
2. **连接机械臂**：连接控制及反馈，沿用RequestControl；不自动上电/使能。仍通过原设备界面人工确认就绪。
3. **连接底盘/升降**：建立既有通信连接；连接成功不代表运动安全或到位。
4. **检查机械臂反馈**：显示实际六轴、位姿、力/力矩、模式和反馈年龄；要求已使能空闲且反馈新鲜。
5. **仅J1/J2精调**：从实测角生成一次偏移，等待实际到位后结束，不启动电批、不自动返回。
6. **仅卡入/拧紧/退出**：当前位置直接执行接触装配，不先走粗定位或视觉偏移，必须人工确认位置正确。
7. **单目标全流程 / 从目标连续运行**：消费原规划任务的快照，执行：
   `底盘（若有）→ 升降（若有）→ 粗定位 → J1/J2模拟精调 → 卡入/拧紧/退出 → 复位 → 下一目标`。

每次实物运行前都必须重新勾选确认；修改参数会取消确认；确认不写盘。
取得流程占用后先串行发送机器人Stop并确认空闲，避免交接前已发指令残留；这不是自动上电/使能。
有任务运行时不能再启动原单步/连续/离线流程，不能抢占Python手动正反转，也不能直接切换离开页面。

## 规划与复位注意事项

- 先在原仿真页生成带目标编号/阶段信息的任务。实物流程不会临时从视觉编造完整路径。
- 路径每段关节变化都要满足配置上限；若拒绝，先重新规划/细分任务，不能靠关闭检查放行。
- 任务已有 `ReturnArm` 就用其规划路径；如果末目标没有复位任务，使用该目标已知粗定位路径
  反向走回 `armStartPose`，不直接跳到未经验证的另一组“初始角”。现场确认必须覆盖该返回路径。
- 连续目标要求上一复位终点与下一粗定位起点一致；不一致时提示开启“移动前复位”并重新规划。
- 接触退出后实际位置不一定精确回到粗定位终点；第一段复位同样从实际关节检查变化量，超限停止，
  不自动用未知路径补偿。单目标重跑也不是断点续跑：先人工确认底盘/升降/机械臂起点。
- 这不是新的碰撞规划器；关节边界/到位检查不能代替机械臂扫掠空间、工具和工件碰撞验收。

## 实时同步与停止

“实时反馈 → 仿真显示”可在实物执行中切换，只调用 `RealRobotFollower` 写仿真执行器，
不把显示值反发给机器人。面板允许机械臂/升降分别按有效反馈更新；未连接/过期轴不跟随。
原“全流程验证（模拟）”仍保持离线和禁止真机跟随的规则。

停止会取消后续阶段、关闭接触真实运动许可，并尝试停止机械臂、电批、底盘、升降。
如果机器人停止/外部占用释放不能确认，保持流程锁，不自动复位、不去下一目标。
处理现场异常后可点“重试停止确认并解除本机流程锁”，不会续跑原任务。
底盘3003应答不是独立的物理静止证明；升降沿用寄存器105停止。软件停止不是硬件急停，
网络断线、主线程/进程退出不能保证停止送达，必须使用设备硬件急停和现场监护。

**按用户要求保留的已知风险：升降超过原等待期限仍会继续后续阶段。**
本轮没有把它说成到位成功保证；只修补Stop后旧async延迟不得再写启动触发。
实际测试务必监护升降；这条旧规则未解决前，不能宣称无人值守全流程已验收。

## Python 与 Unity 怎么对接

- 仍由Unity独占机械臂Dashboard/Feedback。J1/J2及粗定位/复位由新实物接口下发，
  以实际反馈闭环确认；普通手动命令被互斥拦截。
- 到接触阶段才临时开放本机网关真实权限。Python通过19120请求位姿/六维力/相对运动，
  不另连机器人；退出接触阶段关闭许可。实物流程期间拒绝模拟客户端抢占反馈。
- Python正式入口仍为非0910的V26文件，0910原算法主体通过 `servo_contact_cycle.py` 集成，
  原始0910资料文件不作为新启动入口。
- 新增9100桥接命令 `configure_contact:<JSON>`；返回 `contact_api_version=2`、
  `configuration_id`、电批地址。Unity核对配置回执后才运行，真实启动必须先配置。
- `ServoTighteningController`现在会解析Python回复的`ok`，不再把“收到一行失败回复”当成功。
- 电批连接/采集和曲线仍由正式V26服务处理，9101曲线接口未变。启动驱动服务不是纯无设备检查：
  既有服务会尝试电批连接及初始化，所以只在明确选择接触实物测试后自动启动。
