## 历史：2026-10-30 接口4适配问题修复

本节优先于旧记录中的“接口3/尚未修复”描述。上一轮JSON端口统一保留：机械臂连接采用
已保存现场JSON，不回退场景旧30005；本轮不改变任何现场IP/端口/限位/力阈值或实际配置文件。

### 修了什么

1. **卡入第一步误报六维目标。** `unity_robot_client.move_original_interval` 没有预计算目标时，
   不再发送 `expected_target:null`，而是省略可选字段。真实Unity JsonUtility会把显式null数组
   变成空数组，导致之前被长度检查拦住；省略后保持null，Unity按已有GetPose/RelPointTool
   正常计算目标。有六维预计算目标的退出仍发送原目标，并继续核对漂移、有限值和长度。
   没有删除网关校验，也没有新增一次卡入目标预计算往返。
2. **普通复位/停转被当成人工取消。** 通用hard_stop_driver、回位前quick_stop_for_home及回位后
   fast_stop_after_home_reverse不再设置stop_requested，也不清除此标志。只有明确的用户停止/
   故障中止入口锁存取消；新一次显式操作准备才按原规则解除。卡入前hold→拧紧开始、正常结果
   停止→新鲜反馈确认、反转前后普通停止现在可以组合执行。人工停止在准备中到达时仍会阻止
   后续正转，停止/复位本身不能恢复已经取消的任务。
3. **电批无反馈时证据不足。** 每连接维护有界tool_io诊断，随status/cycle-failure返回；新增
   `[ToolTrace]`约每秒一行及连接/断线事件，通过Unity入队显示、写入现场报告日志。
   不增加电批查询/运动命令，不擅自改变帧长/协议/反馈模式；没反馈仍拒绝卡入，不假造0转速。
4. 接口升到4，Unity准备/启动/周期轮询拒绝旧服务，避免只换软件界面却继续使用接口3旧进程。
   算法策略名、方向、原件数值算法和28Nm目标不变，机器人仍只由Unity连接。

### 怎么看新电批证据

`cycle-failure.json`的tool.tool_io、服务status.tool_io，以及run.log/stop-diagnostic.log里的
`[ToolTrace]`包含同一组连接级计数。重新连接后connection_id增加，计数重置，不能跨连接相加。

| 字段/现象 | 可以说明什么 |
| --- | --- |
| rx_bytes=0 | 这次连接尚未收到字节；TCP连通不代表已回传 |
| rx_bytes>0、feedback_frames=0 | 收到过内容，但尚无通过当前解析/滤波的有效反馈；看原始片段及拒绝计数 |
| framing_rejects>0 | 帧候选长度/尾部/CRC不合格的拒绝次数，不是准确的“丢包数” |
| parse_rejects>0 / filter_rejects>0 | 分别为完整帧解析拒绝/扭矩有效性滤波拒绝；仍不计作有效反馈 |
| last_rx_hex / last_tx_hex | 最近接收片段前96字节/最后普通控制发送前32字节，不是全量抓包 |
| last_error / last_rx_age_s | 最近IO错误（最多240字符）/最近收字节距今时间；收字节年龄不等于有效反馈年龄 |

真正停转门槛仍看独立live_speed、feedback_age、无错误以及稳定时间；device_error=-1可能只是
“尚无有效反馈”的本地缺省值，不应直接解释成驱动器真实报警。若依旧报EXIT_BLOCKED，保留
整份新报告及Player.log；不要为了制造反馈先强制转动电批，或勾选绕过停转检查。

## 现场操作变化

1. 完整重新构建 Linux 到**新目录**，部署整个目录。必须包括 ExternalCode 下全部运行脚本，
   尤其新增的 `cr10af_exit_optimized.py`，不能只换可执行文件或某一份 Python。
   先正常停止旧流程并关闭旧拧紧服务；新版拒绝把旧服务/旧网关当作新版运行。
2. 保留原 IP、端口、工具号、User、六轴限位和底盘/电缸设置。打开“现场联调 / 参数”，
   核对本次工具坐标系：**新版 +X 卡入，-X 退出，与旧软件相反**。机械臂世界/基坐标轴、
   Unity 视图朝向不能代替工具轴。未核对前不要勾选许可或执行。
3. 核对后勾选“新版方向：已现场核对工具+X卡入/-X退出”，保存参数，再勾选本次安全确认。
   旧 JSON 缺 `positiveXInsertionConfirmed` 时为 false，不能静默反向运行。
   方向框会将当前内存配置补齐新字段；**只有点击保存参数才写配置文件**。
4. 新增参数（已有字段维持原值）：

   | 字段 | 默认值 | 含义 |
   |---|---:|---|
   | `positiveXInsertionConfirmed` | false | 新方向许可，须现场核对后显式勾选 |
   | `exitStageTimeoutSeconds` | 90 s | 退出内部预算；不是运动固定等待时间 |
   | `contactLateralTrigger` | 18 | 卡入横向搜索触发评价值 |
   | `contactLateralClear` | 12 | 卡入横向搜索解除评价值 |
   | `contactLateralSlow` | 12 | 卡入横向减速评价值 |

   原 `lateralLimitN` 仍作为横向硬停止上限（默认 20），不会自动扩大到同学原件的 26。
   解除值 < 触发值 < min(26, 硬上限)，减速值 ≤ 触发值；这些是原加权横向评价，不是纯 N。
   新默认 18/12/12 是为匹配保留的现场 20 硬上限，不宣称与原件 24/18/18/26 的参数相同。
   若现场已采用更低硬上限，需人工相应填写更低触发/解除/减速值；不自动放宽保护。
5. 卡入继续使用 `contactSpeedMmS`（默认 1.2）和 `contactStepMm`（最大段长，默认 2），
   新算法还受 1.5 s 连续段周期约束，默认首段通常最多约 1.8 mm，不保证实际平均速度。
   退出取原配置与补丁上限中更严格者：速度≤0.6 mm/s、普通段≤0.15 mm、有载段≤0.05 mm。
   每段检查/停止是新退出策略自身要求，不会把粗定位路径改成逐点停稳。
6. `contactStageTimeoutSeconds` 现在对应卡入；退出独立使用新字段。外层完整周期预算
   自动包含卡入、退出、拧紧、缓冲和停止余量。20 mm 退出在 0.6 mm/s 下仅理论运动就
   ≥33.3 s，受力减速、采样、通信、逐段检查还会增加耗时。90 s 不是任意工况都足够，
   超时失败要检查数据和现场，不反复自动拉出。
7. `originalContactTiming` 字段保留兼容旧配置/诊断；**新版接触算法始终使用同学的有限时长
   ServoP 节奏**，不再用它选择旧算法。新接触权限不改粗定位/返程轨迹的发送方式或保护。

## 不变的入口及运行规则

- 原连接面板、底盘手动、现场测试按钮不重新制作。单独卡入/退出仍只执行选中的机械臂动作，
  不调用电批正反转；因此单独测试时须人工确认电批已停转、工具允许脱离和当前可用行程。
  单独退出不会根据上次请求距离自动补偿实际插入误差，也不自动回几何原点。
- 正式开始运行仍是粗定位→末点确认→人工继续（视觉跳过）→接触流程→成功后返程/下一目标。
  新接触流程：电批停止请求及新鲜停转确认→+X 卡入→缓冲→拧紧→停止及停转确认→缓冲→
  再核对停转→-X 优化退出。不会同时运行同学独立 GUI 的另一套自动周期。
- 停转按原程序速度回传原始值绝对值≤1、无设备错误、反馈年龄≤0.25 s、反馈在本次检查后更新、
  持续约0.3 s判断；结果后的检查还要求本次 run_id、结果后台处理完成和停转确认。
  不能把速度单位擅自写成 rpm；软件低速证明不等于扭转载荷/机械约束已释放。
- OK/NG 锁存不等于停转完成。通信/反馈失效、设备 NG、取消、超时或 EXIT_BLOCKED 不自动退出。
  NG_SLIP/JAM 只有确认停转后才尝试机械臂退出，最终仍保留 NG，不报告装配成功或自动进下一目标。
- 普通段末停止与用户全局停止分别处理；停止确认失败保持现有流程锁，不自动重连续跑/反转解卡。
  停止/结果线程未结束时不直接关闭拧紧服务。程序强杀/断电不能当作硬件急停。

## 代码如何改造

- `ExternalCode/cr10af_hybrid_x.py`：新版 EMA、滞回、有限搜索及自适应推进保留；
  `lateral_state`、`lateral_search` 使用 AST 回归对照同学新原件。删除机器人直连实现，
  读数/位移统一调用 UnityRobotClient。单独 CLI 默认退出，未加 execute 仅打印计划。
- `ExternalCode/cr10af_exit_optimized.py`：来自同学退出补丁，保留小步、减载、实测投影、
  跟踪/姿态/横偏/行程检查；仅改共享会话接入与停止/关闭错误处理，不把收尾异常吞成成功。
- `ExternalCode/servo_contact_cycle.py`：唯一接触周期调度，统一新方向，补齐新参数，
  插入前和退出前的停转条件、run_id 关联及取消。当前接口4/策略/方向能力回执防混用旧进程。
- 电批主脚本：保留现有本机控制/曲线服务和模拟隔离；移植同学的结果线程、时间窗口判据、
  拆包/CRC、看门狗、单调时钟、同快照 Agg 保存。不启动原件机器人子进程或独立自动周期。
  新增 live_speed 与旧曲线末个 speed 分开，避免结果冻结后把旧速度当停转反馈。
- `unity_robot_client.py`、`DobotController.Gateway.cs`：增加有权限的只读工具偏移目标计算，
  只返回目标不运动。若之后实际目标相对预计算漂移>0.01，拒绝发送；不会开放任意原始命令。
  同 User/Tool 的真实 GetPose 和实测退出投影仍用于核验，interval_elapsed 仍不是到位。
- `FieldCommissioningSettings/Panel`：补齐旧 JSON 的明确默认值、方向许可和独立预算，
  不新建控制界面；新方向同步到 MotionDiagnostics 的参考轴。
- `ServoTighteningController`：核对服务4/策略/能力/本次配置及方向回执；退出单测及完整周期
  使用新的预算；正常结束/异常获取本次周期报告，不混用其他任务结果。
- `RunDataSession.Evidence`：将完整计划、载荷/搜索/实测移动历史作为 `algorithm_result` 事件
  存到现有 `commands.jsonl` 的 detail 中，关联原目标/阶段/运行ID，不假装是发给设备的命令。
  后台队列/分卷和导出白名单沿用原机制，不将大量历史塞进项目摘要数据库。
- 电批 CSV/PNG 保存到 `Application.persistentDataPath/ServoLogs`（由软件传 SERVO_LOG_DIR），
  不要求安装目录可写；本次报告带对应文件路径。它们仍是独立电批曲线文件，不自动加入
  运行档案 ZIP，异常时请同时保留相应曲线和完整现场报告。
