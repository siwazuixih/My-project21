# 运行指令与设备反馈档案：使用说明

日期：2026-10-28。当前为源码功能及无硬件回归，不代表实物验收；旧TEST包不会自动增加功能。档案标识为`metadata.json`中的`schema=device-run-data-v1`。

## 入口和保存位置

不增加保存开关，开始运行时自动记录。在项目管理中打开对应项目的“项目运行记录→查看详情”，顶部有“打开数据目录”和“导出数据ZIP”，下方显示数据状态。界面只读取小型索引，不加载整份轨迹。

- 正式真实运行/现场单项：复用本次`CommissioningReports/<时间-随机编号>`目录；原configuration、trajectory-plan、motion.csv、停止诊断仍保留。
- 原通讯下发、普通仿真/离线模拟及独立手动调试：新建`Application.persistentDataPath/RunData/<运行ID>`。每次独立目录，不覆盖旧运行。
- ZIP统一写到`Application.persistentDataPath/RunDataExports/`，导出成功会显示完整路径。同一次可以重复导出，每次新文件。无需额外Python包或文件选择器。
- Linux的persistentDataPath通常在用户配置目录下，具体以本机运行详情/`[RunData] 数据记录目录`日志为准，不写死用户名或Company/Product名称。数据库仍保存项目/概要/目录索引，不把全部采样行放入LiteDB。

尚未结束/未完成刷盘的记录不允许从按钮导出，稍后重新打开详情或点击打开目录刷新状态。异常退出的旧档案可能一直`completed=false`，可打开目录检查/手工复制，不能伪装成完整ZIP。旧版本记录没有新档案，界面会提示，不会倒推或补造历史数据。源目录被移动/删除也会明确提示。

## 文件和字段

| 文件 | 说明 |
| --- | --- |
| `metadata.json` | schema、运行/项目ID、来源、模式、模拟标记、应用版本和程序集buildId、参数快照文本、起止UTC、完整性、行数/丢失数/结束时在途数、频率上限和分卷限额 |
| `commands.jsonl` | 一行一个JSON事件；机械臂/底盘/电缸实际通信入口的尝试、写入/库调用返回、应答、接受或失败 |
| `robot-feedback.csv` | 六轴实际角度/速度、末端XYZ/RXRYRZ、模式、User/Tool、设备时间戳、反馈序号/年龄、新样本标记、当前控制器命令ID、有效性 |
| `lift-feedback.csv` | 实际高度/速度/原转矩值及各字段独立有效性/年龄，连接代次和成功读取序号 |

没有对应采集时，相应CSV可能不存在，metadata行数为0；这表示未采集，不表示设备没动或实际为0。分卷名为`commands_0002.jsonl`、`robot-feedback_0002.csv`等，读取时要带上所有分卷。每个CSV分卷都有相同表头。

运行明细原“力矩/角度”列仍指电批结果，不会把机械臂J1～J6角度填进该列；机械臂数据在独立CSV中。保存功能不补造原本未采集到的电批力矩/角度。

所有行共用运行ID、目标/阶段、UTC与从本次档案开始的单调相对时间。UTC可能受系统校时影响，比较时长优先使用`elapsed_s`。目标0表示初始化/未绑定具体目标；手动调试没有正式任务目标。`connection`是对应通道的连接代次，不等同于命令ID，不同设备/机械臂控制和反馈通道的代次不能直接互比。

### 指令：记录下发事实，不用计划冒充已发送

JSONL的`payload`保存原始Dashboard命令、底盘API+JSON，或Modbus功能码/从站/地址/寄存器值及已知浮点解码。`device`为robot/chassis/lift；`endpoint`取实际socket远端，未连接时明确标记，不根据修改后的UI IP猜测实际端点。

- `send_attempt`：准备尝试；可能随后被权限/连接/参数或取消检查拒绝，不代表已写入。
- `packet_prepared`：底盘已生成包；detail含实际包hex，native_sequence含实际流水号。
- `write_completed`：机械臂/底盘异步写调用完成，不等于控制器接受或实物执行。
- `library_call_returned`：电缸同步NModbus调用已返回；**无法取得精确OS写入时刻**，不冒充上面的异步写入时间。
- `reply_received`：设备原应答；电缸仅能记录“NModbus已校验响应”的库返回事实，不伪造原始响应字节。
- `accepted`：原协议检查通过。仍不是到位/停稳证明。
- `failed`：保留异常类型与原因；超时可能已经部分下发，不代表设备一定没有执行。
- `phase`/`recording_end`：记录阶段及档案收尾，不是额外控制命令。

`command_id`是本档案的本地关联号，用来连接上述多个事件；机械臂排队运动/坐标切换的实际返回编号在accepted的`native_sequence`，反馈中的`active_command_id`是控制器当前执行编号。查询返回的单个数值不当作命令ID。底盘用实际流水号关联；电缸没有同等的控制器命令ID，主要按时间/阶段对照，不能声称硬件同步或逐点一一对应。

单位：机械臂关节deg、关节速度deg/s、末端mm/deg；实际User/Tool单独保存，末端不冒充Unity世界坐标。电缸寄存器2025为转换后的目标mm、2001为mm/s，原CDAB寄存器同时保留；转矩字段为现有控制器原值`torque_raw`，没有未经标定就改称Nm。底盘dist/x/y为m、angle/theta为rad、vx/vy为m/s、w为rad/s，以具体API报文为准。

### 反馈：复用现有读取，不增加查询

- 机械臂从现有有效反馈状态采样，上限10Hz；电缸从已有读取结果采样，上限5Hz。不改30004/30005选择，不新增GetPose/GetAngle或Modbus查询，不调整运动间隔/CP/停止/到位逻辑。
- 实际采样受Unity帧率及设备回传频率影响，不保证精确10/5Hz，更不是保存每个原始包。机械臂`new_sample=false`表示当前快照不是新的有效序号，不能按保存行数计算实际回包数。
- 机械臂valid还检查年龄和有限数值；无效行可能保留原始旧值供诊断，必须按valid筛选。`age_s`是最近有效反馈到达软件后的年龄，不是相机/机器人端到端网络延迟。
- 电缸位置/速度/转矩是分次读取，非同一硬件时刻；分别记录有效性。断线、读取失败或过期字段留空，不用0代替失败，真正有效的0仍保留。0.6秒有效窗口只服务档案标记，不放宽既有运动保护。
- 粗定位、人工等待、接触/INSERTING或EXITING、返程和停止可按阶段筛选；计划仍保存在trajectory-plan.json，原接触几何测量仍在motion.csv，不被新档案替代。

不能把“刚下发目标”与“同一时刻反馈”直接相减当稳态误差：控制器可能仍在执行之前的排队点，CP也可能不经过中间点。实际到位仍按原独立完成检查，保存功能不新增运动或自动补偿。

## 自动运行、手动与模拟的区别

- 已有正式运行会话时，三设备指令和反馈归入同一运行，原首因和完成结果不改变。
- 选中项目、但没有正式会话时，首次普通通信会建立“手动调试/通信记录”，记录结果只标“已下发/未验收到位”，不会标成完整任务成功。主动断开任一设备、离开场景、启动正式任务/切换项目或退出会结束该手动会话。
- 完全没有会话时，孤立Stop/电缸105/底盘3003不会为了保存而先初始化数据库，优先原停止路径；已有运行/调试会话中的停止会照常保存。未选择项目则不创建项目档案。
- 仿真/离线会话明确simulated=true，只保存模式/参数/阶段，不把当时连接着的实物反馈混入，也不伪造实物指令/角度。原离线模拟服务隔离仍保持；本版没有额外采集MuJoCo动画轨迹。

## 数据量、失败和退出边界

数据文本由一个后台写入任务按队列顺序追加，约每秒刷新文件；普通历史摘要仍沿用原数据库保存方式。采集不等待磁盘、不等待队列空间，也不持有设备锁做磁盘IO；少量字符串/采样处理仍有CPU开销，不能承诺实际时序绝对零变化。

每队列上限4096行且约2Mi字符，单文件目标上限20MiB，在完整行之间分卷；单行本身可能超过文件目标大小。指令不主动抽样，但队列满/超大行不能无条件无损：明确累计droppedRows并标数据不完整。不会静默丢弃后宣称保存完成；不会自动删除旧运行，仍须关注工控机磁盘空间。

写失败会在日志/详情提示，不能覆盖原设备异常或拖住停止。会话关闭时仍有在途指令记录pendingAtClose，之后即使迟到回调结束也保留“不完整”；迟到记录绝不写入新会话。文件完整性与任务结果独立：任务成功但保存失败，不会被伪改为设备失败，也不能把数据状态说成完整。

metadata.completed表示记录器收尾，不是实物到位；约1秒刷盘不是掉电零丢失或每行fsync。退出/强杀/断电可能丢失尾部，尤其不能因程序消失而推断设备停稳。正常结束后等`[RunData] 数据保存完成`或详情显示保存完成再导出，急停优先于保存。

## 部署和验收

1. Unity退出Play，等待脚本导入/Console无编译错误；不需手动新增场景绑定。完整构建Linux到新目录，构建后处理会附带本说明`RUN_DATA_STORAGE.md`。
2. 先用离线模拟结束一次，检查运行详情按钮、旧记录兼容及simulated=true；确认没有实物反馈混入。检查中文路径/窄屏布局/导出ZIP/重复导出，不在编辑器直接让实物运动。
3. 在已核对安全条件下监护一次单目标或现有单测。结束后对照运行ID/metadata行数、实际MovJ/ServoP、底盘3055/3056、升降2001/2025及反馈；CSV编号读成文本，避免Excel把64位ID转浮点损失精度。
4. 提供整份原报告和数据ZIP；ZIP只含上述新数据文件，不含configuration/原motion.csv/run.log，所以排查原流程问题仍需原报告目录。没有图表回放、磁盘自动清理、原始TCP全包或额外设备查询功能。

无设备回归已覆盖后台刷盘/分卷/满队列/磁盘失败/路径冲突/迟到结果/模拟隔离/ZIP白名单/参数快照，以及生产机械臂、底盘和电缸采集钩子。Unity实际界面、Linux文件管理器打开效果、磁盘空间不足的现场体验及真实运动时序仍需人工验收。本次不修改场景/版本号、Python算法、软限位或电缸原超时继续策略。
